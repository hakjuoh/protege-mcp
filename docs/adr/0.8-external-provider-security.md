# 0.8 external-provider security and cache

- Status: accepted for implementation
- Date: 2026-07-20

## Context

Version 0.8.0 adds provider-backed term discovery to a loopback-first desktop product. A checked-out project
is not trusted to choose where an owner credential is sent, provider adapters must not bypass project egress
policy, and vendor responses may echo credentials, queries, redirects, or opaque signed URLs into every error,
cache, log, audit, and MCP-result sink. Existing import networking is host-aware, but credentialed provider
traffic needs the stricter exact-origin and secret-value boundary defined here.

## Decision

### Supported profile and SPI

0.8.0 supports the OLS4 REST search/term profile. An in-process fake implements the same provider-neutral SPI
for deterministic tests. BioPortal, LOV, and project-specific adapters are extension targets, not supported
0.8.0 profiles. The SPI receives a normalized request and a restricted executor; it never receives a raw HTTP
client, credential, filesystem path, or live ontology.

`ProviderResult` and `ProviderPage` are immutable core contracts. Search is exactly one provider per request,
uses deterministic normalized ordering/deduplication, and returns an opaque bounded cursor rather than a vendor
URL. The adapter records its exact profile/API identity and maps failures to stable provider error codes.

### Authority and egress

Policy v2 can enable a provider, constrain ontologies/languages, and request a `credential_id`. The credential
identifier is only a request. Owner-controlled configuration binds the id to provider id, exact HTTPS origin,
authentication scheme, and optionally a project-policy fingerprint. Both bindings must match. A project cannot
introduce a custom origin for an existing credential.

One executor performs HTTPS-only origin parsing, DNS resolution, private/link-local/loopback rejection unless
the owner explicitly created a test-only loopback profile, per-address connection checks, response byte/time
limits, and a second address check before each retry. Ambient proxy credentials are ignored. Credentialed
redirects are never followed. An uncredentialed redirect is stripped of sensitive headers and followed only
after the target origin passes the full authorization check. Provider request retries are read-only, bounded,
and disclosed; 429 uses a capped `Retry-After`.

### Credential storage

The initial backend is an owner-only local record store below the existing Protégé MCP home. Creation and every
open verify regular-file, no-symlink, owner-only permissions where the OS exposes them; a platform that cannot
meet the documented permission contract refuses credential persistence. Policy, ontology files, project
sidecars, preferences exports, audit, manifests, caches, exceptions, and tool results never contain secret
values. Credential management is local configuration, not an MCP tool.

### Cache and redaction

Caches are partitioned by provider profile, exact origin, project fingerprint, and non-secret credential
generation/scope fingerprint. Sensitive normalized requests use an owner-local HMAC rather than plain
SHA-256. Every hit rechecks policy, endpoint, credential binding/generation, and network authority; credential
rotation/deletion invalidates the partition. They have fixed entry/byte/body/TTL bounds, atomic insert, LRU
eviction, and no authorization headers, opaque vendor cursors, signed URLs, or raw sensitive query text.
Negative caching is
limited to deterministic not-found responses; auth, rate-limit, timeout, 5xx, and malformed responses are not
negative cached.

Every issued secret is registered as a redaction canary for the request lifetime. URL userinfo, authorization
schemes, known and provider-declared secret field names, query values, headers, vendor bodies, exception causes,
and redirect targets are sanitized before any sink. Redaction failure fails the request closed and does not
cache the response. URI components are checked after bounded iterative percent decoding; unresolved deeper
nesting fails closed, while ordinary non-sensitive query and fragment IRIs remain valid ontology identifiers.
Public errors contain stable code, bounded sanitized message, retryability, and non-secret details only.

Opaque cursors expire after five minutes and are capped at 32 per principal, 256 per backend, and 256 KiB each.
Revocation, window close, and restart erase them; exhaustion fails closed without evicting active cursors.
Broker grant/client fences that a backend does not acknowledge are persisted owner-only and retried for the
broker lifetime, including against windows that register after the revocation request. The bounded write-ahead
journal is replayed into OAuth state before serving after a restart, and only a sealed quiescent shutdown may
compact it after durable OAuth replay. Heartbeat-stale or unregistered but OS-live processes, plus endpoint
incarnations removed or replaced by a heartbeat, remain in a revocation-only quarantine and never in normal
routing until the PID exits. This prevents a frozen or incompletely stopped backend from outliving its fence.
Active registration is capped at 32 processes with 128 windows each, and retired endpoints have a separate
4,096-entry bound that fails closed.

## Consequences

- Provider networking is plugin-only in 0.8.0; headless stdio and one-shot CLI stay offline.
- A provider outage affects only the provider request and a policy gate that explicitly requires fresh provider
  evidence. It never blocks unrelated local editing, QC, or release work.
- OLS4 can run without a credential. Credential contracts still ship and are tested so later profiles do not
  invent a weaker path.

## Verification

- Loopback fakes cover DNS/address changes, redirects, header stripping, timeouts, 429/5xx, oversized/malformed
  bodies, vendor secret echoes, retry bounds, cache TTL/eviction/partitioning, and simultaneous projects.
- Canary secrets are injected into every input and failure surface; tests scan returned values, logs, audit,
  cache bytes, exception chains, and URLs for the exact canary.
- Rotation/deletion/scope-change tests prove old credentialed entries cannot be served, and the HMAC keying
  prevents offline dictionary recovery of sensitive queries.
- Permission/symlink tests cover the credential and cache roots on every claimed packaged platform.
- Ordinary `mvn clean verify` is network-isolated after dependency priming; scheduled OLS4 canaries validate
  only endpoint/profile shape and do not golden search ranking.
