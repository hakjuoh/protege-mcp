# 0.8 contracts, policy v2, and compatibility

- Status: accepted for implementation
- Date: 2026-07-20

## Context

The current public snapshot preserves a 0.5.0 plugin baseline and shallow documented result fields. Policy v1
rejects unknown fields and its effective digest includes loader normalization. Adding providers, mapping stores,
job quotas, or materialization defaults directly to v1 could silently change old digests and invalidate saved
previews. Version 0.8 needs nested typed contracts and an explicit policy migration boundary before new tools.

## Decision

### Immutable baselines and schemas

Before new registrations, capture immutable 0.7.2 plugin (85 tools/11 prompts) and headless stdio
(`get_headless_capabilities` plus seven project/audit/release tools) goldens. The catalog gains nested JSON
output schemas and a common error schema with stable `code`, bounded
sanitized `message`, optional non-secret `details`, and `retryable`. Built-in tools cannot register without
input, output, error, and capability declarations. Schema validation is recursive and rejects unknown required
fields, invalid enum/state combinations, and mismatched handlers.

0.8 snapshots cover plugin/headless metadata, input/output/error schemas, policy v1/v2 schemas and normalized
digests, core contract JSON, job transition tables, and documented result examples. A 0.8 golden is immutable
after release. Additive fields are allowed only when optional; enum extension requires an explicitly open enum.
Stable error codes include provider, credential/egress, proposal, mapping/revision, job/quota/ownership,
artifact, materialization, model/policy conflict, authorization, and confirmation families.

### Policy v2

Policy v1 parsing, default insertion, validation results, canonical serialization, and effective digest remain
byte-for-byte unchanged. New authored fields require `version: 2`; the loader dispatches version-specific
schema and normalization and never silently upgrades or rewrites a file. Validation of v1 may return a separate
non-digest migration recommendation. Template generation accepts an explicit version/profile.

Policy v2 adds:

- `external_terms.providers[]`: supported profile, enabled flag, exact origin alias, ontology/language filters,
  freshness/TTL, required-evidence scope, and credential id request;
- `mappings`: confined path, predicate/source/license rules, many-to-one/cycle policy, and required findings;
- `jobs`: allowed types, workers/queue/per-principal/retention bounds that may only tighten product maxima;
- `materialization`: allowed reasoners/categories/destinations, source-write permission, and count/byte/time caps.

Endpoint aliases and credential bindings remain owner-local and are not serialized in policy. A provider marked
required can block only a provider reuse/mint decision or an explicitly configured provider-evidence stage; it
never blocks unrelated editing. V2 normalization and digest include resolved defaults deterministically.

### Surface and migration

Provider networking is plugin-only. SSSOM and reasoner/materialization core services are shared by plugin and
headless adapters. Async jobs are plugin-only in 0.8. One-shot CLI stays synchronous. Unsupported surfaces
return no registration rather than a tool that always errors. Cross-surface fixtures compare only declared
common contracts and record intentional differences.

No automatic policy migration command writes a project in 0.8. `validate_project_policy` reports a structured
v1-to-v2 recommendation, and `write_project_policy_template version=2` produces a reviewed new template. Users
adopt v2 explicitly.

## Consequences

- The first implementation slice is contract hardening; no feature tool lands before it.
- Old policy digests and cached revision envelopes remain valid when running 0.8.
- Typed error/output snapshots make later simultaneous code-and-doc removal detectable.

## Verification

- Golden tests pin all 0.7.2 and 0.8 surfaces, recursive schemas, handlers, capabilities, docs, and result/error
  examples. Mutation tests remove/rename nested fields, states, codes, and registrations and must fail.
- Policy fixtures prove every v1 result/digest is identical before/after the v2 loader, v2 defaults are stable,
  unknown fields/versions fail, and migration diagnostics never alter the digest.
- Cross-adapter tests assert shared services and explicitly verify absent provider/job registrations headlessly.
